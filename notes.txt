THE SETUP

I am working on the branch feature/local_sci.

We have around 40 services. Config lives in a separate config repository, with
folders per environment: QA01, QA02, QA03, dev and perf. All of that has always
worked, and we used to bring the services up locally by pointing at that config.

WHAT BROKE

All our secrets were recently moved to CSM. Since that migration, the config files
no longer work for local runs -- the applications will not come up, because the
secrets are not present.

MY CURRENT WORKAROUND, AND WHY I WANT TO DROP IT

In the config repository I checked out a commit from just before the CSM migration
started, so that I can still bring my application up locally.

The problem is that my branch is pinned to that old commit, so when anyone makes new
config changes on top of the latest main I cannot pull them. It is getting messy.

I also do not want to fix this by editing project files locally -- if I modify things
in my working copy to get the app up, someone else pushes a change and my setup breaks
again. I want my config to always be the latest main, and I want the local-only part
handled entirely through VM options or something else supplied at runtime.

HOW I RUN SERVICES LOCALLY TODAY

For any environment: inside the project there is a folder called app, and inside that
a project called config, which holds these files. In that JSON file, line 3 is a field
called JAVA_DEVOPS_OPTS -- those are the VM options we use.

In those VM options I override paths: the external YAML file, the bootstrap YAML, and
the CSM YAML. I replace each of those paths. That is how we have always brought the
applications up locally.

One thing in my favour: I still have the actual secrets locally, from when the older
config was working.

Also, if a property moved somewhere or changed name, we can still keep it the same in
the application YAML -- the latest config can stay exactly as it is.

   as the latest code, and diff them.

4. Work out the VM options pattern that lets me run the latest main config locally

5. Then come back and review the plan with me. Deep research first, then the plan.
