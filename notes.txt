# Project: account-service-parent — Enum Serialization Fix

I want to fix an issue with a clear, streamlined approach rather than patching things in random places. Work autonomously, but stop and ask me whenever you hit one of the stop points listed below.

## Context

account-service-parent is a production microservice. It originally had two kinds of endpoints coexisting:

1. **OpenAPI spec endpoints.** A small set of IVR endpoints (around 5–6; verify the exact count) were defined in the OpenAPI spec. The Maven build generates the API interfaces, and our controllers implement them.
2. **Hand-written Java endpoints.** All remaining endpoints were implemented directly in Java classes, with no OpenAPI spec.

## Recent migration

We recently migrated the hand-written endpoints (around 17–19) to the OpenAPI spec, so all endpoints are now spec-based. For these migrated endpoints, we kept the old Java-class endpoints in place and appended `/legacy` to their paths.

The service layer was not touched. At the controller layer, we created new request/response classes generated from the spec and mapped them to the existing domain classes so behavior wouldn't change. Only the controllers differ between the OpenAPI endpoints and the legacy Java endpoints.

## The problem: enum serialization

- The legacy (Java-class) endpoints serialized enums using the Java enum **name**.
- The OpenAPI-generated code serializes enums using the enum **value**.

To preserve legacy behavior, I created a custom enum serializer (as part of the recent migration) and registered the specific enums that should serialize by name instead of value.

However, the original IVR endpoints use enums nearly identical to those in the migrated endpoints, and the IVR endpoints serialize by **value**. Because both share the same OpenAPI spec, the IVR enums were modified during migration, and now serialization is inconsistent. We believe every enum is potentially affected.

## Sources of truth

- **IVR endpoints:** the `before-migration` branch (see Step 1).
- **Migrated endpoints:** the `/legacy` endpoints in the current branch.
