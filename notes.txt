## Goal

## Observed behavior (confirmed by me, this is fact)
The code and the config repo are identical locally and in the environment. Nothing is changed between them.

Locally:
- No Authorization header → the request passes.
- Garbage or malformed token → the request passes.

Deployed (dev, QS01, etc.):
- No Authorization header → rejected; the header is mandatory.
- Garbage token → rejected with 400 and a "malformed token" error.
- Valid token from the TIA URL → the request passes.

Your job is to find, in the code and its dependencies, exactly what produces this behavior.

## Rules
- No guessing. Every statement in the document must cite evidence: a file path plus the class, method, annotation, or config key. If you can't find evidence for something, say so explicitly in the document instead of filling the gap.
- Never invent config keys, property names, library APIs, URLs, or environment values.
- Don't stop at this service's src folder. The validation very likely comes from an internal TIA library:
  - Run `mvn dependency:tree` and identify the TIA library (and any other internal security libraries), with exact versions.
  - Find the jars in the local Maven repository, unpack them, and read the sources jar or decompile the classes.
  - Check Spring auto-configuration inside the jars: META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports, spring.factories, @Conditional* annotations, @Enable* annotations, @Import, and component scanning of library packages.
  - Check filters, interceptors, security config, and aspects, both in this service and in the libraries.
- To explain the local vs environment difference, check everything that can differ between the two: environment variables and settings injected by the OpenShift deployment, active Spring profiles, Vault values, the FCM config for each environment, network reachability of any token validation endpoint, and conditions inside the library itself.
- If you get stuck or need information only I have (for example, OpenShift deployment settings you can't see), stop and ask me.
