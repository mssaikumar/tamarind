# Verification: Enum Behavior After the Fix

The enum serialization fix is complete. Now verify it end to end. This is a verification pass only: report problems, and don't change anything without asking me.

## Step 1: Confirm the setup

1. Check that the local `before-migration` branch still exists. If it doesn't, ask me for the commit ID.
2. From the code, list:
   - The **IVR endpoints** (the OpenAPI endpoints that existed in `before-migration`).
   - The **migrated endpoints** and their `/legacy` counterparts.
3. Show me both lists and **wait for my confirmation** before proceeding.

## Step 2: Verify the IVR endpoints

For each IVR endpoint, trace every request and response model, including nested models at every depth. Every enum must be **exactly the same** in the current branch as in `before-migration`: same constants, same names, same values, same serialization behavior.

## Step 3: Verify the migrated endpoints

For each migrated endpoint, compare every enum in the OpenAPI version against the enum used by its `/legacy` counterpart, and write a parameterized JUnit test using `@EnumSource` so every constant is covered. For each constant, check:

- **Constants match:** nothing exists on one side but not the other.
- **Serialization:** the JSON output matches what `/legacy` produces.
- **Mapper:** works in both directions (domain ↔ generated) with nothing lost or mismatched.
- **Deserialization:** for enums in requests (POST, PUT, PATCH, and query or path parameters), the OpenAPI version accepts the same input as `/legacy`.

## Step 4: Report

Give me a summary table with one row per endpoint and enum, showing pass or fail for each check. For every failure, explain what's wrong and propose a fix, but **don't apply it until I approve**.

## Guardrails

- Never assume. Verify everything against the code or with a test.
- Legacy enum classes may come from a library, so look in `target/classes` or the local Maven repository. If you can't find one, give me the expected path.
- The verification tests are temporary. List them at the end so I can remove them.
